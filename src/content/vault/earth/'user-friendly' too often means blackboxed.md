- usability doesn't inherently mean removing agency / choice / learning curve from the user
- usability means allowing exploration, recovery from mistakes, explainable and predictable error states, etc
- simple interfaces are often better, but not always better.
- exposing functionality of software should not mean dangerous error states, software should wherever possible avoid features that would be capable of dangerous error states in the first place, select the tech that makes it functionally impossible
- write more documentation, write better documentation
- let users loose with the tools and expect them to break it but build so it is maintainable, repairable, by the user, wherever possible
- some demographics do need simpler / friendlier / one direct pathway / less agency offered but this shouldn't mean blackboxing all functionality by default
